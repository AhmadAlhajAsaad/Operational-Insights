## Samenvatting

Dit document definieert de functionele requirements voor het veilig ontsluiten en beheren van gebruikersgegevens uit Atlassian-producten via de Atlassian Admin API. De integratie moet gebruikersbeheer mogelijk maken zonder dat API-credentials worden blootgesteld aan de frontend.

---

## Scope

### In Scope

- Ophalen van gebruikersgegevens uit Atlassian Organization
- Filteren en zoeken van gebruikers
- Ophalen van gebruikersdetails (profiel, status, toegang)
- Beheren van gebruikersrollen en toegang tot producten
- Uitnodigen van nieuwe gebruikers
- Opschorten en verwijderen van gebruikers
- Synchronisatie van Atlassian-gebruikersdata met lokale database

### Out of Scope (MVP)

- Twee-factor authenticatie management
- Directory synchronisatie (SCIM)
- API token management voor gebruikers
- Audit log management
- Advanced permission schemes

## User Stories

### US-1: Ophalen van Gebruikerslijst

**Als** Administrator
**Wil ik** een overzicht kunnen zien van alle gebruikers in onze Atlassian Organization
**Zodat** ik weet wie toegang heeft tot Atlassian producten

**Acceptance Criteria:**

- Lijst toont alle gebruikers in de organizatie
- Gebruikers kunnen gefilterd worden op status (active/inactive)
- Gebruikers kunnen gefilterd worden op product access
- Paginering is beschikbaar voor grote datasets
- Zoeken op naam of email is mogelijk

---

### US-2: Bekijken van Gebruikersdetails

**Als** Administrator
**Wil ik** gedetailleerde informatie kunnen bekijken van een specifieke gebruiker
**Zodat** ik hun toegang en status kan controleren

**Acceptance Criteria:**

- Detail view toont: naam, email, account status, account type
- Product access overzicht is zichtbaar (Jira, Confluence, etc.)
- Groep memberships zijn zichtbaar
- Laatste activiteit datum is beschikbaar (indien beschikbaar)
- Account creation date is zichtbaar

---

### US-3: Filteren op Product Access

**Als** Administrator
**Wil ik** kunnen filteren welke gebruikers toegang hebben tot specifieke producten
**Zodat** ik license usage per product kan analyseren

**Acceptance Criteria:**

- Filter op Jira Software access
- Filter op Confluence access
- Filter op Jira Service Management access
- Filter op Bitbucket access
- Combinatie van filters is mogelijk

---

### US-8: Synchroniseren van Gebruikersdata

**Als** Systeem
**Wil ik** automatisch gebruikersdata synchroniseren tussen Atlassian en onze database
**Zodat** onze applicatie actuele data heeft

**Acceptance Criteria:**

- Synchronisatie draait automatisch (dagelijks)
- Nieuwe gebruikers worden toegevoegd aan lokale database
- Gewijzigde gegevens worden bijgewerkt
- Status wijzigingen worden gesynchroniseerd
- Manual sync trigger is beschikbaar voor administrators

---

### US-9: Zoeken en Filteren

**Als** Administrator
**Wil ik** geavanceerd kunnen zoeken en filteren in gebruikersdata
**Zodat** ik snel specifieke gebruikers kan vinden

**Acceptance Criteria:**

- Zoeken op email adres
- Zoeken op naam (first/last name)
- Filteren op account status
- Filteren op account type (atlassian, customer, app, etc.)
- Filteren op product access
- Filteren op groep membership
- Combinaties van filters zijn mogelijk

---

### US-10: Export van Gebruikersdata

**Als** Administrator
**Wil ik** gebruikersdata kunnen exporteren naar CSV
**Zodat** ik externe analyses kan uitvoeren

**Acceptance Criteria:**

## Functionele Vereisten

### Data Collection (MUST HAVE)

1. **Gebruikers Ophalen**
   - Systeem moet alle gebruikers kunnen ophalen uit Atlassian Organization
   - Paginering moet worden ondersteund (max 100 per page conform API limits)
   - Cursor-based pagination voor consistente resultaten

2. **Gebruikersdetails Ophalen**
   - Systeem moet gedetailleerde info ophalen per gebruiker
   - Inclusief: accountId, email, displayName, accountType, accountStatus
   - Inclusief product access en groep memberships

3. **Filteren en Zoeken**
   - Zoeken op email (exact match en partial match)
   - Filteren op account status (active, inactive, closed)
   - Filteren op account type (atlassian, customer, app)
   - Filteren op product access via group memberships

4. **Product Access Bepaling**
   - Bepaal welke producten een gebruiker kan gebruiken
   - Gebaseerd op groep memberships
   - Match groep namen met product names (jira-software-users, confluence-users)

### Data Synchronisatie (MUST HAVE)

9. **Automatische Sync**
   - Dagelijkse synchronisatie van gebruikersdata
   - Nieuwe gebruikers toevoegen aan lokale database
   - Bestaande gebruikers bijwerken
   - Status wijzigingen detecteren

10. **Manual Sync**
    - Administrator kan handmatig sync triggeren
    - Progress indicator tijdens sync
    - Summary van wijzigingen na sync

### Security en Privacy (MUST HAVE)

11. **API Key Protection**
    - API keys worden NOOIT blootgesteld aan frontend
    - Alle Atlassian API calls gaan via backend proxy
    - Frontend gebruikt JWT tokens voor authenticatie

12. **Data Masking**
    - Email adressen worden gemaskeerd voor non-admin users
    - Persoonlijke data conform GDPR handling

13. **Activity Logging**
    - Alle user management actions worden gelogd
    - Inclusief: wie, wat, wanneer
    - Voor audit trail

## Integration Points

### Backend API Endpoints (to be created)

```
GET    /api/atlassian/users                   # List users with filters
GET    /api/atlassian/users/:accountId        # Get user details
GET    /api/atlassian/users/export            # Export to CSV
GET    /api/atlassian/users/sync/status       # Get sync status
```

### Atlassian API Endpoints (used internally by backend)

```
GET    /admin/v2/orgs/{orgId}/users           # List users
GET    /admin/v2/users/{accountId}            # Get user details
PATCH  /admin/v2/users/{accountId}            # Update user
```

Zie [API Documentatie](/workspace/docs/api/atlassian/user-management-api.md) voor details.

## Business Rules

### License Management

1. **Active User = License Consumer**
   - Een gebruiker consumeert een license als:
     - account_status = "active"
     - gebruiker is lid van product-specifieke groep
     - groep geeft toegang tot een product

2. **Suspended User = No License**
   - Opgeschorte gebruikers consumeren geen license
   - Hun data blijft bewaard
   - Ze kunnen worden gereactiveerd

3. **Deleted User = License Released**
   - Verwijderde gebruikers geven license vrij
   - Data wordt verwijderd (conform Atlassian policy)
   - Actie is irreversibel

### Group-Based Access

4. **Product Access via Groups**
   - Gebruikers krijgen product access via groep membership
   - Standaard groepen: jira-software-users, confluence-users, etc.
   - Custom groepen kunnen ook product access geven

5. **Organization Membership**
   - Gebruikers moeten lid zijn van de organization
   - Verified domains voor automatic access
   - Invites voor andere domains

## Error Handling

### Expected Errors

1. **User Not Found (404)**
   - Display: "Gebruiker niet gevonden"
   - Action: Refresh lijst

2. **Insufficient Permissions (403)**
   - Display: "Onvoldoende rechten voor deze actie"
   - Action: Contact administrator

3. **Rate Limit Exceeded (429)**
   - Display: "Te veel requests, probeer over {X} seconden opnieuw"
   - Action: Automatic retry met exponential backoff

4. **User Already Exists (409)**
   - Display: "Gebruiker met dit email bestaat al"
   - Action: Toon bestaande gebruiker

5. **Invalid Email (400)**
   - Display: "Ongeldig email adres"
   - Action: Validatie feedback in form

## Performance Requirements

1. **Response Times**
   - User list: < 200ms voor 100 gebruikers
   - User detail: < 100ms
   - Sync: < 30 seconden voor 1000 gebruikers

2. **Caching**
   - User list gecached voor 5 minuten
   - User details gecached voor 2 minuten
   - Cache invalidation bij mutations

3. **Pagination**
   - Max 100 users per page (Atlassian API limit)
   - Cursor-based pagination voor consistentie
